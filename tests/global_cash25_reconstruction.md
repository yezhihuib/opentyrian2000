# Shared Cash25 / Cash50 / Cash75 / Gem100 / Gem250 structural-shim verification

The test compiles current production global cash25/Talon owners, identity helper,
shared pixel dispatch, root lifecycle, actual explosion allocator, and fade paths.
Enemy/record types are extracted from current native headers. Original shape,
record and palette bytes pass only through stdin and are never saved.

Checks cover all 33 unchanged resources across five independently bound profiles, both supported internal densities,
six coin phases or sixteen repeated/reverse gem phases per profile, eight fixed-popup draws per profile, independent alpha/HSV value arithmetic,
wrong roles and sources, incomplete/duplicate writes, warm-cache mutation,
observed invalidation followed by restoration including transferred contributions,
resource rejection, cached surfaces, and actual extracted fade logic.

This is not engine-native gameplay, collision, original enemy allocator, or GPU
proof. Body initialization uses a bounded structural fixture; separate identity
and native tests must establish those claims. Other families besides Talon are
isolated with disabled shims; their interactions require separate native evidence.

A missing/corrupt resource or invalid sibling source conservatively rejects the
shared five-profile cash/gem owner. This is intentional all-five-or-classic
behavior, not per-coin failure isolation. Cross-profile type, source and record
substitution must not borrow another profile’s native allocation witness.
