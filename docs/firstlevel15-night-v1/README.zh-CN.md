# Hard 首关夜间高清

验证范围，2026-10-14。源码/单元检查、一次有限的原生 Hard 开场和另一次受保护的
中段/Boss 诊断已通过。最终夜间/圣诞组合源码也通过两组有限单元检查及 Linux 构建。
此项扩展提供夜间首关的高清合成支持，不代表自然 Hard 生存、完整通关或 Windows 运行验收。

## 适用范围

既有 `--manual-hd-assets` 参数新增支持：普通数据、本地单人 Full Game、第一章、
原版 Hard 及以上难度所选中的物理关卡 15。这是 Hard+ 的首关变体，不是菜单中的
第十五关。原有物理关卡 9 的准入条件和画面裁切方式保持不变。

新路径必须取得原版 PIC3 场景许可，并匹配调色板 5、有效源资源及受支持的索引/RGBA
表面布局。圣诞数据、演示、联网、双人/Galaga 及其他特殊模式不在此扩展范围内。
未知输出类型、索引或归属不一致、不兼容资源会拒绝高清合成；表面布局不安全时
不进行高清呈现。

沿用现有手动高清启动方式和普通菜单、原版操作，无新增启动参数或美术包。
原版游戏数据仍须另行提供。不启用手动高清参数时，普通启动保持原版显示。

## 显示行为

原版索引光照循环保持不变。合成高清前，先使用同一帧的源索引和光源坐标核对
实际目标索引。

- 几何上处于亮区的原创像素逐位保留。
- 所有非亮区分支使用已批准的 Option 1：以原版目标调色板颜色为锚点，
  将原创 RGB 细节的偏差斜率限制在四分之一以内，必要时按可用颜色范围进一步缩小；
  偏差采用半入舍入，已合成的 alpha 不重复计算。
- 原版索引恰好不变时，非亮区细节仍会收缩。原有锐利光锥边界保持不变。
  低于目标锚点的通道可能数值上升，因此不是统一压暗所有 RGB。
- 原版归属像素使用实际目标调色板颜色。原有色相 8、亮度 8 的现金文字局部保留原版，
  并接受原版光照。
- 仅改变场景裁切区域。HUD 合成、玩法、事件、RNG 及玩家/光源更新保持不变。
  既有渐变使用已合成输出，呈现时不重复施加光照。

## 已完成验证

独立优化版及 ASan/UBSan 单元检查覆盖完整通道域、原版索引几何、像素归属、
拒绝路径、HUD 边界和渐变/呈现行为。一次未添加保护的普通菜单 Hard 开场得到
23 次观测完成帧和 5 张实际 640×400 截图：Hard 选中菜单及 4 张游戏画面。
光锥出现，并响应原版向右、向左输入；4 组保留的索引/调色板数据独立复算与
原版循环一致，高清输出与原生渲染器读回一致。

另一次受保护的原版事件推进到达 7,429 tick。独立审阅接受五个选定游戏窗口：
146/147 坦克弹、完整 20 部件 Boss、武器 81 能量弹，以及成功发射并叠在核心上的子机。
360 次抽查索引核对全部一致；五组保留数据独立核对 242,880 个索引单元及
1,280,000 个原生像素，均无差异。现金和 HUD 可辨认；所保留 Boss 血条全部处于亮区，
不能据此声称暗区血条画面已验证。

受保护诊断会改变受伤响应、玩家绘制及后续轨迹，结论仅限这些选定渲染样本，
与未加保护的开场分开。它不证明普通玩家样式、玩法轨迹不变、全部朝向或全部弹道。
各对照重建均来自对应的同次候选运行，不是独立基线游戏运行。实际运行证据仅为
Linux SDL dummy/software、8 倍源素材、原生 2× 输出；4/8 倍素材单元检查及派生图
不等于原生 4× 运行验收。未观测角色及后续内容、实体 GPU/输入/音频、性能及
Windows 均不在这些有限验收范围。最终组合源码整合没有新增游戏运行。详见[验证清单](VALIDATION.md)。
